# OrbitShift 0.1.2

## Accessibility that survives updates

OrbitShift now uses a persistent code-signing certificate, so macOS can recognize new versions of the app and preserve their Accessibility permission. Local Dev builds also reuse a persistent identity. No Apple Developer subscription is required.

**One-time setup after upgrading from 0.1.0 or 0.1.1:** open OrbitShift → Settings → System and grant Accessibility to the new app. If the old entry is already enabled but access is missing, remove that entry with **−**, add the current app with **+**, and enable it. Later updates signed with this certificate keep the permission. Production and Dev have separate grants.

Builds and release packaging now reject missing or mismatched signing identities instead of falling back to ad-hoc signing. Sparkle continues to verify updates using the existing update-signing key.

The app is still not Developer ID signed or notarized by Apple. First-launch macOS confirmation may still be required; keep Gatekeeper enabled. You do not need to install a certificate or change system trust settings.

## Разрешение сохраняется после обновлений

OrbitShift теперь использует постоянный сертификат подписи: macOS узнаёт новые версии и сохраняет их разрешение «Универсальный доступ». Dev-сборки также используют постоянный сертификат. Подписка Apple Developer не нужна.

**После перехода с 0.1.0 или 0.1.1 нужно один раз выдать доступ заново:** OrbitShift → Настройки → Система. Если старая запись уже включена, но приложение не видит доступ, удалите её кнопкой **−**, добавьте текущую копию кнопкой **+** и включите доступ. Следующие обновления с этим сертификатом сохранят разрешение. У production и Dev отдельные разрешения.

Сборка и упаковка релиза останавливаются, если постоянный ключ отсутствует или не соответствует сертификату. Прежняя ad-hoc-подпись больше не используется. Проверка обновлений Sparkle продолжает работать с прежним ключом.

Приложение по-прежнему не подписано Apple Developer ID и не прошло нотариализацию Apple. При первом запуске может потребоваться подтверждение macOS; отключать Gatekeeper, устанавливать сертификаты или менять доверие в системе не нужно.
